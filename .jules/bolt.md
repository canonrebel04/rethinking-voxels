## 2024-05-24 - GLSL `pow(x, 2.0)` Optimization
**Learning:** In this GLSL shader codebase, using `pow(x, 2.0)` is inefficient because the compiler evaluates it using `exp2(2.0 * log2(x))`. The `pow2(x)` function provided in `shaders/lib/common.glsl` evaluates directly to `x * x` and avoids this performance bottleneck. Additionally, `common.glsl` is not included in all library files (such as `endPortalEffect.glsl` and `irisRequired.glsl`), meaning inline multiplication `(x * x)` must be used if `pow2` is unavailable. Lastly, mixed integer and float variables within math functions like `max(0, ...)` should explicitly use float literals (e.g., `0.0`) to avoid implicit type casting overhead and driver compatibility issues.
**Action:** When working in GLSL, always replace `pow(..., 2.0)` with `pow2(...)` where `common.glsl` is available, or use inline multiplication `(x * x)` where it is not. Ensure integer arguments in math functions (like `0` or `1`) are cast to float (e.g., `0.0` or `1.0`) to avoid overhead.
