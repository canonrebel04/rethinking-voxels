## 2024-10-15 - Optimizing clamp division patterns
**Learning:** In GLSL shaders, divisions are computationally expensive. We found common clamp patterns like `clamp(x + c, 0.0, max_val) / max_val` being used across 26 files (e.g., `sunVisibility`). These can be mathematically simplified to `clamp(x * (1.0/max_val) + (c/max_val), 0.0, 1.0)`. Not only does this replace the expensive division with a cheaper multiplication, but changing the target range to exactly `[0.0, 1.0]` allows GLSL compilers to map this to a zero-cost hardware `saturate` instruction modifier, providing a measurable performance win in hot rendering paths.
**Action:** When auditing shaders, actively look for expressions normalizing values via division inside or outside clamps. Refactor them into multiplication before clamping, and ensure the final clamp bounds are `0.0, 1.0` to trigger hardware saturate optimizations.
