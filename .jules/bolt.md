## 2024-10-23 - FMA + saturate optimizations in shaderpacks
**Learning:** In GLSL shaders, expressions like `clamp(x + c, 0.0, max_val) / max_val` are a common pattern for things like sun visibility. Transforming these algebraically into `clamp(x * (1.0/max_val) + (c/max_val), 0.0, 1.0)` is extremely powerful. Not only does it replace an expensive division instruction with a multiplication, but normalizing the clamp bounds to exactly `[0.0, 1.0]` allows modern GLSL compilers to apply a free `saturate` instruction modifier to the preceding Fused-Multiply-Add (FMA) operation (`mad_sat` in assembly). This condenses multiple ALU instructions (add, min, max, multiply/divide) into a single hardware instruction.
**Action:** Always look for opportunities to refactor `clamp()` boundaries to `[0.0, 1.0]` when a subsequent division or multiplication scales the result anyway. It forces the compiler into the optimal `saturate` path.
