## 2024-05-25 - GLSL pow() function macro safety
**Learning:** In GLSL shaders, extracting complex mathematical expressions out of the built-in `pow(x, 2)` or `pow(x, 2.0)` into local float variables (e.g., `float t = x; result = t * t;`) avoids macro double-evaluation risks and improves consistency across different driver compilers, which sometimes fail to properly optimize `pow` with constant exponents natively. Also, explicitly using float literals like `0.0` or float casting `float(i)` instead of integers `0` inside functions like `max()` prevents shader compilation failures.
**Action:** Always replace `pow(x, 2)` and `pow(x, 2.0)` with variable multiplication `t * t` pattern in GLSL for safety and micro-performance. Explicitly cast integer types to floats when doing float operations.
